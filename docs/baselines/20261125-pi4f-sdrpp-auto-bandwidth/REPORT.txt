SDR++ Soapy Auto-bandwidth fix — 25 November 2026

Installed on pi4f-trixie (192.168.6.163), board #2 HiF, for the Mac SDR++
client / Pi SDR++ server setup. This is a separate SDR++ source-module fix;
the earlier CaribouLite Soapy sample-rate fix remains installed unchanged.

Problem: SDR++ selectBwBySr initializes its fallback to bandwidthList[1],
the narrowest real bandwidth after the Auto sentinel. With 4 MS/s selected,
no advertised CaribouLite bandwidth reaches that rate (maximum 2 MHz), so
Auto fell back to 20 kHz and enabled narrow software filtering. The operator
confirmed selecting 2 MHz manually allowed the stream to start.

Fix: initialize the fallback to bandwidthList.back(), the widest available
bandwidth. Retain the existing reverse search for the smallest bandwidth
that reaches the requested rate. When no such bandwidth exists, clamp to
the widest available. The method retains its existing sorted-list contract
and nonempty-list precondition; its caller requires more than two entries.
Manual bandwidth selections do not invoke this method.

Validation:
- The source-level regression compiles the actual selection method with mock
  logging. It fails on original code and passes on corrected code on both
  the Mac and Pi. It covers all eight native rates, exact/below/above limits,
  forward/reverse transitions and a different device's bandwidth ceiling.
- Built only the source module against the installed SDR++ core; ldd -r
  found no undefined symbols. Build commands/hashes retained in build.json.
- A temporary localhost server using the candidate module and copied test
  configuration received HiF at 430.1 MHz, Int8, no compression, Auto selected.
  Tested 4 MS/s for 10 s, 2 MS/s for 3 s, then 4 MS/s for 5 s. Each start
  logged Auto bandwidth 2000000 Hz. UI snapshots confirmed Auto remained
  selected throughout. Throughput matched requested rate within 0.3%, and
  maximum inter-packet gaps were below 17 ms. No TX was performed.
- Normal server restarted as pi (PID 3240), listening at 0.0.0.0:5259.
  Verified its mapped module inode matches the replacement file.
